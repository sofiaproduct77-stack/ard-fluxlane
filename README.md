# FluxLane (ARD)

**Веб-платформа дорожной аналитики** для Смоленской области: мониторинг датчиков, интерактивные карты, статистика интенсивности, построение маршрутов и админ-импорт из Excel. Курсовой / дипломный проект **ARD** — современный публичный портал + админка для специалистов ЦОДД.

### Зачем

- **Граждане и СМИ** — новости, проекты, контакты, прозрачность по дорогам.
- **Аналитики** — карта детекторов, кластеры маршрутов, скорость и интенсивность, кратчайший путь A→B.
- **Администраторы** — импорт детекторов и проходов ТС, сборка графа дорог, JWT-вход.

**Стек:** Node.js · Express · Sequelize · SQLite · Leaflet · Socket.IO · Docker.

## Интерфейс

- `index.html` — обзор (KPI, карта датчиков, сводная аналитика)
- `monitoring.html` — оперативный мониторинг и лента событий
- `analytics.html` — аналитика интенсивности и скорости по участкам
- `traffic-analysis.html` — интерактивная карта, маршруты, совместное движение
- `import-data.html` / `admin.html` — импорт данных и администрирование

## Обзор возможностей

    Технологии
    - Frontend: HTML, CSS, JavaScript (Vanilla), Leaflet.js, Socket.IO client
    - Backend: Node.js (Express), Sequelize (по умолчанию SQLite), Socket.IO server
    - Хранилище: SQLite (database.sqlite) по умолчанию; опционально MySQL
    - Форматы данных: CSV/XLSX (библиотека XLSX)

Ключевые возможности
- Интерактивная карта: детекторы, дороги (рёбра), треки ТС, Top‑N маршруты
- Оптимальный маршрут: выбор двух точек кликом (строго A→B)
- Автосборка: треки из проходов и рёбра между детекторами строятся автоматически после импорта
- Реальное время: уведомления через WebSocket и авто‑обновление слоёв
- Админ‑панель: импорт детекторов/проходов, запуск построения треков/рёбер, аналитика
- Авторизация: JWT для доступа к админ‑функциям

Структура проекта
- server.js — запуск Express/HTTP и Socket.IO
- backend/config/database.js — настройка Sequelize (SQLite по умолчанию)
- backend/models/*.js — модели (Detector, Edge, VehiclePassage, VehicleTrack, User и др.)
- backend/routes/*.js — API (traffic, auth, импорт, аналитика и т.д.)
- traffic-analysis.html + src/traffic-analysis.js — карта и логика UI
- admin-dashboard.html + src/admin-dashboard.js — админ‑панель
- uploads/ — загружаемые файлы
- database.sqlite — база по умолчанию

Основные сущности
- Detector — узел графа (датчик) с координатами
- Edge — направленное ребро между детекторами, может содержать геометрию (LineString)
- VehiclePassage — факт прохода ТС через детектор (vehicleId, detectorId, timestamp)
- VehicleTrack — упорядоченная последовательность детекторов ТС за интервал (со скоростью/временем)

Фронтенд: страница карты
Файлы: traffic-analysis.html, src/traffic-analysis.js
- Карта Leaflet (L.map), стилизация, скрытие атрибуции OSM/Leaflet по требованию
- Слои: детекторы, дороги, треки, Top‑N маршруты, оптимальный маршрут
- Легенда: цвет/толщина по интенсивности, отдельный чип для оптимального маршрута
- Панель инструментов: компактная, вертикальная/правая раскладка
- Боковая панель: списки/подробности по выбранным объектам
- Оптимальный маршрут (только “Клик по карте”):
  - Нажать “Выбрать точки”, поставить максимум две точки (A и B)
  - “Найти маршрут” → поиск ближайших детекторов, запрос к /shortest-path, отрисовка
  - “Очистить” → удалить точки и маршрут

Сценарии
1) Отображение детекторов и дорог
   - При загрузке запрашиваем /api/traffic/detectors и /api/traffic/roads и рисуем слои
   - При событиях ‘data_updated’ по WebSocket обновляем соответствующие слои

2) Импорт в админ‑панели
   - Импорт детекторов → сохранение → автопостроение рёбер (если есть треки) → событие по WS
   - Импорт проходов → сохранение → автосборка треков → автопостроение рёбер → событие по WS

3) Ручное построение
   - Кнопки “Построить рёбра” и “Построить треки” в админ‑панели

4) Оптимальный маршрут A→B (клик)
   - Поставить A и B → фронтенд находит ближайшие детекторы (Haversine) → /shortest-path
   - Бэкенд запускает Дейкстру по графу Edge → возвращает путь и дистанцию → визуализация

5) Top‑N маршрутов (кластеры)
   - /api/traffic/clusters по интервалу времени → агрегация треков по сигнатурам
   - Возврат статистики (count, intensity/hour, avgSpeed, avgTravelTime) → полилинии с разной толщиной/цветом

Реальное время
- Socket.IO в server.js (app.set('io', io))
- При импортах/построениях отправляем io.emit('data_updated', …)
- Клиент перерисовывает слои и показывает уведомления

API (основное)
Базовый путь: /api/traffic
- GET /detectors → список детекторов
- GET /roads → рёбра с геометрией
- GET /tracks?from&to&vehicleId → треки
- GET /clusters?from&to&topN → топ‑маршруты и их статистика
- GET /shortest-path?fromDetectorId&toDetectorId → кратчайший путь
Авторизация
- POST /api/auth/login → { token }
- GET /api/auth/verify → { user }
- GET /api/auth/profile → { user }

Алгоритмы
- Ближайший детектор: Haversine по всем детекторам, минимальное расстояние
- Кратчайший путь: Дейкстра по направленному графу детекторов/рёбер
- Кластеры Top‑N: сжатие последовательностей детекторов в сигнатуры маршрутов, агрегирование метрик

Импорт данных (поток)
- Детекторы: парсинг XLSX → Detector
- Проходы: парсинг XLSX → VehiclePassage
- Треки: из проходов формируются последовательности → VehicleTrack
- Рёбра: из треков формируются пары (a→b), геометрия подтягивается через OSRM/GraphHopper (если доступно)

Развёртывание

- Старт: npx pm2 start server.js --name "codd-app"; npx pm2 logs codd-app
- Проксирование домена: на виртуальном хостинге настраивается провайдером/панелью

Эксплуатация
- Логи: npx pm2 logs codd-app
- Перезапуск: npx pm2 restart codd-app

- Данные: uploads/ — файлы импорта; database.sqlite — база
