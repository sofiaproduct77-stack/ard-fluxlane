### 42
Современный рынок цифровых услуг предъявляет высокие требования к скорости создания и сопровождения веб-сайтов. Сегодня наличие собственного представительства в сети нужно не только крупным компаниям: сайты востребованы у малого бизнеса, специалистов свободных профессий, образовательных и сервисных проектов. При этом разработка «с нуля» на чистом коде остаётся трудоёмкой: требуется знание вёрстки, клиентских и серверных технологий, адаптивной вёрстки и публикация результата. Классический путь через заказ у разработчика или самостоятельное написание HTML/CSS/JavaScript часто оказывается избыточным по срокам и стоимости для типовых задач. В связи с этим растёт спрос на визуальные конструкторы, где сайт собирается на холсте, а структура, стили и публикация ведутся в единой среде без обязательного ручного программирования каждой страницы.

### 43
Актуальность темы определяется распространением no-code / low-code подходов и потребностью в практико-ориентированной платформе, которая совмещает визуальный редактор, администрирование проектов и выдачу готового сайта.

### 44
Цель курсового проекта - спроектировать и реализовать веб-платформу Studio для визуального создания сайтов, обеспечивающую работу с проектами, редактирование страниц на холсте, адаптивные экраны, сохранение документа, медиатеку и администрирование контента в упрощённом контуре.

### 45
В качестве методологии реализации выбрана итерационная модель разработки в сочетании с методом прецедентов. Принцип создания проекта состоит в том, что система строится короткими управляемыми циклами. Сначала фиксируются ключевые прецеденты, для них определяются акторы, основной и альтернативные потоки, входные и выходные данные. Такой подход снижает риск накопления ошибок, позволяет рано получить работающий прототип и согласовать архитектуру с реальным поведением пользователя.

### 97
1.5 Обоснование выбора языка программирования, среды разработки, библиотек и инструментов

### 98
Выбор инструментов выполнен в соответствии с целью курсового проекта и с учётом требований к веб-платформе визуального создания сайтов. Клиентская часть реализована на TypeScript: язык сохраняет возможности JavaScript в браузере и добавляет статическую типизацию, что снижает число ошибок на этапе сборки и упрощает сопровождение модели документа, интерфейса редактора и обращения к API. Серверная часть реализована на Go: язык удобен для REST-сервиса, работы с хранилищем проектов и стабильной работы в контейнере.

### 99
Для интерфейса кабинета и визуального редактора выбран React. Компонентный подход позволяет разделить холст, панели и кабинет проектов, а обновление состояния интерфейса при редактировании и автосохранении выполняется без лишней сложности. Сборку клиента обеспечивает Vite; состояние редактора хранится в Zustand. В качестве среды разработки используется Visual Studio Code: она удобна для TypeScript и Go, интегрируется с Git и терминалом и поддерживает работу с файлами всего проекта.

### 100
Для хранения проектов и документов сайта применяется SQLite. Такая СУБД не требует отдельной установки на учебном стенде, легко переносится вместе с проектом и достаточна для объёма курсового продукта. Развёртывание серверных компонентов выполняется через Docker Compose, что упрощает запуск API и связанных сервисов на локальной машине или VPS.

### 101
Дополнительно используются маршрутизация HTTP на стороне API, средства работы с медиафайлами и современный браузер как среда выполнения редактора. Совокупность выбранных средств покрывает полный цикл разработки: проектирование, реализация, проверка и демонстрация продукта. На защите можно показать работу всех слоёв — от сохранения документа проекта до интерфейса в браузере.

### 102
При выборе клиентского стека рассматривались также Vue и Angular. Vue удобен для одностраничных приложений, Angular даёт больше возможностей «из коробки», но тяжелее для учебного объёма. React выбран как распространённое решение для интерактивных интерфейсов с холстом и панелями. Для сервера альтернативами были Node.js и PHP; Go выбран для выделенного API и контейнерной поставки, при этом TypeScript остаётся основным языком клиентской части. Такой стек обеспечивает воспроизводимый стенд и наглядный результат курсового проекта.

### 105
Общий алгоритм работы приложения рассмотрен от лица пользователя и отражает сквозной сценарий создания сайта. Пользователь открывает кабинет платформы; при отсутствии сессии выполняет вход или регистрацию; создаёт новый проект либо открывает существующий. После загрузки документа открывается визуальный редактор: пользователь выбирает страницу, при необходимости переключает экран (компьютер, планшет, смартфон), добавляет и перемещает элементы на холсте, меняет размеры и оформление. Изменения сохраняются автоматически. При необходимости загружаются медиафайлы и подставляются в элементы проекта. Для проверки результата используется режим превью; при завершении работы пользователь выходит из системы. Ветвления соответствуют повторному открытию проекта, смене страницы или экрана и исправлению элементов после просмотра.

Алгоритм согласован с диаграммой состояний и тестовыми сценариями. Блок-схема общего алгоритма указывается в приложении А (рисунок А.1). Взаимодействие объектов при типовом сценарии отражено на диаграмме последовательности в приложение А (рисунок А.2).

В редакторе единый каркас включает верхнюю панель (страницы, экраны, автосохранение, превью), холст с отображением страницы и боковые панели свойств и структуры. ### 124
Серверная часть реализована в виде API на Go с хранением проектов и JSON-документа сайта в SQLite. При сохранении редактор передаёт документ на сервер; автосохранение периодически фиксирует изменения без отдельного действия пользователя. Клиентская часть редактора реализована на React и TypeScript с сборкой через Vite; состояние редактора хранится в Zustand. Кабинет и редактор используют единый контракт документа: страницы, узлы, экраны, стили и связанные медиафайлы.

### 125
Интеграция модулей выполняется по принципу «контракт JSON + проверка сессии на сервере». Клиент не принимает решений о правах самостоятельно: запросы к чужим проектам отклоняются API. Документ обновляется операциями редактора и записывается в хранилище, что исключает расхождение между отображением на холсте и сохранёнными данными. Такое разделение ответственности повышает надёжность продукта и упрощает тестирование.

### 126
На сервере проверяются обязательные поля форм и запросов (данные входа, идентификатор проекта, тело документа). Неверный логин или пароль возвращает ошибку без раскрытия лишних деталей. Запросы без сессии к защищённым маршрутам отклоняются. На клиенте ошибки API отображаются в интерфейсе, а пустые состояния (нет проектов, пустая страница) сопровождаются понятными подсказками пользователю.

### 189

### 191
Пользователь входит в систему по логину и паролю. После входа открывается кабинет проектов, где видны созданные сайты и действие создания нового проекта.

### 192
Типовой сценарий работы выглядит так. В кабинете создаётся новый проект (задаётся имя сайта) или открывается уже существующий. Далее загружается визуальный редактор: пользователь выбирает страницу, при необходимости переключает экран (компьютер, планшет, смартфон), добавляет и перемещает элементы на холсте, меняет размеры и оформление. Изменения сохраняются автоматически. При необходимости загружаются изображения через медиатеку. Для проверки результата включается режим превью; после просмотра можно вернуться в редактор и продолжить правки.

### 193

### 195
Администратор входит под учётной записью с правами управления. После входа доступен админ-контур: просмотр и управление проектами, базовые настройки. Администратор может контролировать список проектов и служебные параметры платформы.

### 196

### 198
Разработка и эксплуатация программного продукта Studio связаны с продолжительной работой за персональным компьютером. В соответствии с санитарными нормами и правилами по охране труда при работе с ПЭВМ необходимо учитывать вредные и опасные производственные факторы и организовывать рабочее место так, чтобы снизить утомляемость и риск травм.

### 199
К вредным факторам относятся повышенная нагрузка на органы зрения при длительной фиксации взгляда на экране, статическая нагрузка на опорно-двигательный аппарат, нервно-эмоциональное напряжение и шум оборудования. Опасными факторами являются поражение электрическим током при неисправной изоляции, возгорание при коротком замыкании и механические травмы при падении устройств. Эти риски особенно актуальны при многочасовой работе над кодом редактора, отладке API и оформлении пояснительной записки.

### 200
Правильная организация рабочего места предполагает удобную посадку: стопы опираются на пол или подставку, угол в коленях близок к 90°, спина имеет опору, предплечья расположены параллельно столу. Монитор устанавливают на расстоянии 50–70 см, верхний край экрана - на уровне глаз или чуть ниже; клавиатуру и мышь используют без чрезмерного сгибания запястий, а кабели размещают так, чтобы они не мешали передвижению. Освещение рабочей зоны лучше сочетать естественное и искусственное, избегая прямой засветки экрана и бликов: монитор ориентируют боком к окну, при необходимости применяют жалюзи. Освещённость должна быть достаточной для чтения бумажных материалов без резкого перепада яркости относительно экрана; не рекомендуется работать в полной темноте только при свете монитора.

### 201
При непрерывной работе с ПЭВМ устраивают перерывы примерно каждые 45–60 минут на 10–15 минут: выполняют гимнастику для глаз, меняют позу, переводят взгляд на дальние объекты, разминают шею и кисти. Дополнительно полезны микропаузы каждые 20–30 минут и настройка яркости и масштаба интерфейса браузера. Чередование задач - программирование, оформление документации, проверка сценариев редактора - снижает монотонную нагрузку и помогает дольше сохранять внимание.

### 202
Безопасная эксплуатация оборудования включает проверку исправности розеток, шнуров и корпуса перед началом работы. Запрещается вскрывать блок питания и монитор под напряжением; при запахе гари, искрения или перегреве устройство сразу отключают от сети. Жидкости не ставят на системный блок и ноутбук. Используют исправные удлинители без перегрузки, не выполняют самостоятельный ремонт блоков питания и знают расположение огнетушителя. При эвакуации оборудование обесточивают по инструкции учебного кабинета. Помещение следует проветривать; при работе на ноутбуке желательны внешняя клавиатура или подставка, чтобы экран находился на комфортной высоте. При совместной работе за одним монитором обеспечивают достаточное расстояние и угол обзора для каждого участника.

### 203
Для снижения риска потери результатов разработки применяют резервное копирование проектов платформы Studio, базы данных и исходного кода. По завершении работы корректно завершают сеансы среды разработки и сервисов стенда, сохраняют изменения и выполняют резервное копирование. Соблюдение перечисленных требований снижает риск заболеваний и травм, повышает работоспособность разработчика и пользователя платформы и является обязательным условием безопасной разработки и демонстрации программного продукта Studio. В учебном кабинете эти меры дополняются инструктажами по охране труда и правилами пожарной безопасности.
